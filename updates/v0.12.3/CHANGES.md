# v0.12.3 — CalculiX Windows 실행 환경 및 비정상 종료 진단

## 사용자 사례와 확인 범위

- 데스크탑 Windows, CPU 4개, 낙하 최대 증분 0.00001초, 종료 시간 0.001초.
- 안정화 초기/최대 증분 0.01초, 종료 시간 1초.
- 첫 낙하 중 종료 코드 3221225477 = 0xC0000005, EXCEPTION_ACCESS_VIOLATION.
- 제공 로그는 약 0.000126초까지 계산된 뒤 중단됐습니다. 에너지 평형 비율은 약 0.4~2%였으며
  이 부분에 폭발적인 에너지 증가나 NaN은 없습니다. 이것만으로 해석 정확성이나 Windows 충돌 원인을 확정하지 않습니다.
- 첫 낙하가 끝나기 전에 종료되었으므로 안정화 단계는 아직 실행되지 않았습니다.

## 확인한 설정 누락과 변경

동봉 원본 Windows 솔버 소스의 `CalculiXWindowsEnvironment.bat`는
`CCX_NPROC_STIFFNESS=1`을 지정합니다. 빌드 시험 스크립트에도 병렬 계산 시
수렴 문제를 피하기 위해 필요하다는 설명이 있습니다. Manager의 직접 실행에는 이 설정이 빠져 있었습니다.

이번 변경은 CalculiX 자식 프로세스에만 다음 환경을 설정합니다.

- `OMP_NUM_THREADS`, `NUMBER_OF_CPUS`, `CCX_NPROC_RESULTS`: GUI의 CPU 개수.
- `CCX_NPROC_STIFFNESS=1`: 강성 조립 스레드 1개.
- `PRINTF_EXPONENT_DIGITS=2`: 동봉 Windows 환경의 수치 출력 방식.
- 기존 `GFORTRAN_UNBUFFERED_ALL=1`과 솔버 폴더 DLL 경로 우선 사용을 유지합니다.

CPU 기본값은 4개를 유지합니다. PC 전역 환경이나 DLL, 라이브러리를 변경하지 않습니다.
강성 조립 설정 누락은 수정했으나, 이것이 사용자의 접근 위반을 일으켰다는 인과관계는 아직 확인하지 못했습니다.

## 진단 파일

솔버가 비정상 종료되면 해당 단계 폴더에 `solver_failure_report.json`을 저장합니다.

- 종료 코드와 Windows 예외 이름.
- 실제 낙하/안정화 시간 설정, CPU와 실제 스레드 환경.
- 입력 파일 및 CalculiX 실행 파일·DLL의 SHA-256.
- 로그 끝부분, 마지막 진행 시간과 안정 증분.
- 출력 파일 크기, 남은 디스크 공간, 마지막 관찰 정보.

접근 위반 코드만으로 RAM 부족이나 입력 오류를 단정하지 않습니다.
원본 결과를 보존하며 실패한 계산을 정상 완료로 처리하거나 자동 재시도하지 않습니다.
다시 계산할 때 이전 진단 파일도 기존 출력과 함께 `previous_attempt_...`에 보관합니다.

## 적용 및 데스크탑 비교 시험

1. 실패 상태의 Manager와 결과창을 닫습니다. 다른 계산이 실행 중이면 현재 단계 완료 후 일시정지하세요.
2. 업데이트 ZIP 전체 압축 해제 → `apply_update.bat` → 기존 `start_windows.bat` 폴더 선택.
3. 프로그램을 다시 실행하고 **이전 실행 폴더 열기 / 재개**로 실패한 doe 폴더를 엽니다.
4. **폴더를 연 다음 CPU를 1개로 변경**합니다. 불러올 때 기존 CPU=4 설정이 다시 적용될 수 있기 때문입니다.
5. 낙하 최대 증분 0.00001초, 종료 0.001초와 안정화 설정은 유지하고 실패한 낙하를 재실행합니다.

완료된 다른 단계는 유지합니다. 실패한 낙하는 다시 계산해야 합니다.
CPU 1개만 성공하면 병렬 경로를 더 좁혀 확인할 수 있지만, 다른 원인도 추가 확인이 필요할 수 있습니다.
다시 실패하면 `solver_failure_report.json`과 `solver.log`를 함께 확인하세요.

## 실제 시험

Linux CalculiX 2.23, 샘플 Aluminum/Plastic 384 C3D8, Top Face, 높이 1000mm, 갭 0.001mm에서
최대 증분 0.00001초 / 종료 0.001초를 CPU 1개·4개로 실행했습니다.

두 경우 모두 종료 0.001초 도달, 변위·속도·응력·상태 이력 유한성 및 최종 결과 변환 검사를 통과했습니다.
CPU 1/4의 최대 native 응력 절댓값은 약 18.21975175 MPa였습니다.

**이 1ms 시험은 출력 용량을 줄이기 위해 FREQUENCY=500으로 실시했습니다.**
GUI의 실제 FREQUENCY=1 출력과 Windows 실행 파일을 동일하게 검증한 시험은 아닙니다.
별도의 짧은 CPU 4개 시험에서 Manager의 실제 FREQUENCY=1 실행·변환 경로를 확인했습니다.
Windows 접근 위반은 이 환경에서 재현하지 못했으며 패치가 그 충돌을 해결한다고 보장하지 않습니다.
자동 테스트 189개 통과. 새로운 라이브러리나 솔버 다운로드는 없습니다.
