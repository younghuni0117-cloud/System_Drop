# v0.12.2 — 해석 중 완료 결과창의 모듈 경로 오류 수정

## 확인한 원인

사용자 로그의 다음 오류를 대상으로 수정했습니다.

```
Error while finding module specification for 'system_drop.viewer'
ModuleNotFoundError: No module named 'system_drop'
```

메인 GUI는 자신의 위치를 import 경로에 넣지만, 별도 결과창을 `python -m system_drop.viewer`로
실행하면 새 Python 프로세스에는 그 경로가 전달되지 않았습니다.
동봉 Python의 격리 모드 또는 이전 설치의 Python을 재사용하는 경우 결과창이 열리지 않을 수 있었습니다.
이전 Python 환경을 재사용하는 것은 허용하며, 그 환경에 패키지를 다시 설치하지 않습니다.

## 변경

- 모든 PyVista 결과창을 **현재 설치의 절대 경로 bootstrap**을 통해 실행합니다.
- bootstrap이 현재 프로그램 경로를 먼저 추가하고 결과창 인수만 전달합니다.
- 완료한 방향 셋업/낙하/안정화, 전체 결과, 검증 예제에 같은 경로를 적용했습니다.
- 해석 중 완료 버튼 활성화와 독립 결과창 프로세스 동작은 유지합니다.
- 결과창이 비정상 종료되면 viewer.log 끝부분을 메인 로그에도 표시합니다.
- 기존 해석 데이터, native restart, INP와 솔버 설정은 변경하지 않습니다.

## 설치

v0.11.0부터 v0.12.1까지 적용할 수 있는 누적 패치입니다. 이전 패치도 모두 포함합니다.

1. 해석 중이면 **현재 단계 완료 후 일시정지**를 선택하고 실제 대기 상태가 될 때까지 기다립니다.
2. Manager와 결과창을 닫습니다.
3. `system_drop_v0.12.2_update.zip` 전체를 임시 폴더에 압축 해제합니다.
4. `apply_update.bat` 실행 후 기존 `start_windows.bat`이 있는 `system_drop` 폴더를 선택합니다.
5. 기존 `start_windows.bat`으로 다시 실행합니다.
6. 필요하면 상세 옵션의 **이전 실행 폴더 열기 / 재개**로 기존 doe 폴더를 엽니다.

완료된 단계와 결과는 유지합니다. 변경 소스는 backups 폴더에 백업합니다.
라이브러리나 CalculiX를 새로 설치하지 않습니다.

## 검증

- 자동 테스트 **184개 통과**.
- 현재 설치와 다른 위치에서 격리 Python을 실행해 결과창 경로·옵션을 검사했습니다.
- 실제 Linux Qt/VTK에서 완료된 셋업/낙하/안정화 버튼, 전체 결과, 예제의 **5개 별도 창**이
  스크린샷을 생성하고 정상 종료했습니다.
- UI를 진행 중 상태로 두고 독립 테스트 프로세스가 계속 실행됨을 확인했습니다.
  이 검사는 FEM 계산을 반복한 시험이 아닙니다.
- 실제 Windows 실행은 이 개발 환경에서 미검증입니다.
