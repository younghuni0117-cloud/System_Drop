# v0.12.8 — CalculiX 결과 파일 용량과 변환 시간 개선

기존에는 모든 구조 결과 요청을 FREQUENCY=1로 바꿨습니다. Explicit의 실제 증분이 작으면 최대 증분으로 예상한 프레임 수보다 훨씬 많은 FRD/DAT 원본을 기록하고, 변환 후 대부분 버렸습니다. 단순한 메쉬에서도 원본 파일이 매우 커질 수 있는 구조였습니다.

## 변경 내용

- CalculiX의 계산 증분과 FRD/DAT 기록 주기를 분리합니다. 기본은 자동이며 매 계산 증분 기록을 강제하지 않습니다. NODE FILE / EL FILE / NODE PRINT / EL PRINT에 같은 기록 주기를 적용합니다.
- 단계별 변환·저장 프레임 한도는 기본 1,000개입니다. 최대 증분으로 계산한 목표 프레임이 더 적으면 그 목표를 사용합니다. 자동 기록 주기는 목표 간격과 초기 증분 기준값을 참고해 결정합니다.
- 실제 Explicit 증분은 안정 조건에 따라 결정됩니다. 따라서 원본 기록 수·간격은 목표와 다를 수 있으며, 저장 한도는 원본 FRD/DAT의 파일 크기나 원본 프레임 수의 강제 상한이 아닙니다.
- 출력 프레임이 목표보다 적어도 실제 프레임만 변환합니다. 중복 프레임이나 보간 프레임을 만들지 않고 마지막 실제 결과를 반드시 포함합니다. 종료 시간·시간 순서·비유한 수치 검사는 유지합니다.
- DAT 인덱스를 만들 때 모든 행의 수치는 검증하지만, 모든 프레임의 평균 응력/적분점 최대 응력을 미리 계산하지 않습니다. 선택된 프레임을 읽을 때 계산하여 변환 시간을 줄입니다. 기존 None/Simple/Advanced 응력 결과는 유지합니다.
- 첫 낙하·안정화·다음 낙하와 솔버 실행 직전 모두 적용합니다. 이미 완료된 솔버 출력은 다시 계산하거나 덮어쓰지 않습니다.
- 적분 시간 설정, 재료, 접촉, 감쇠 및 native restart의 누적 상태 보존 방식은 바꾸지 않습니다. Abaqus 출력 방식도 유지합니다.

## 사용 방법

1. 단계 완료 후 일시정지하고 Manager와 결과창을 닫습니다.
2. 업데이트 ZIP을 임시 폴더에 풀고 apply_update.bat을 실행해 기존 설치를 선택합니다.
3. 상세 옵션에서 다음 항목을 확인합니다.
   - **CalculiX 기록 주기 (증분): 자동** — 권장 기본값입니다. 1이면 모든 계산 증분, 100이면 100증분마다 기록합니다.
   - **CalculiX 최대 저장 Frame: 1000** — 단계별 변환 프레임 한도입니다.
4. 새로운 해석부터 출력량 감소가 적용됩니다. 기존 실행을 이어갈 때도 아직 계산하지 않은 단계에는 새 설정이 적용됩니다. 각 단계의 output_plan.json과 [출력] 로그에서 적용된 기록 주기를 확인할 수 있습니다.

성긴 기록 주기는 짧은 응력 피크를 놓칠 수 있습니다. 피크 평가가 필요한 구간은 기록 주기를 작게 지정하고 저장 프레임 한도를 늘려 확인하세요. 이 설정은 시간 적분 정확도를 낮추지 않지만 결과의 시간 해상도에는 영향을 줍니다.

기존에 이미 만들어진 수십 GB 원본은 자동 축소하거나 삭제하지 않습니다. 완료 결과의 변환에 실패했다면 기존의 **이전 실행 폴더 열기 / 재개** 기능을 사용하면 완료 상태 검증 후 솔버 재계산 없이 개선된 변환을 재시도합니다. 대용량 원본은 여전히 순차 검사 시간이 필요합니다. 동작 중인 솔버의 파일은 직접 삭제하거나 수정하지 마세요.

## 검증

- 자동 테스트 214개 통과, 이후 출력·변환 관련 16개 재확인.
- Linux CalculiX 2.23, 실제 샘플 Top Face 충돌, 종료 0.000006 s, 동일한 적분 설정, 기록 주기 1 ↔ 자동(10) 비교:
  - FRD+DAT: 70,408,888 → 7,478,016 bytes, **약 89.4% 감소**.
  - 변환: 5.48 → 0.86초, 두 경우 모두 6프레임 저장.
  - native co / vold / veold / sti / xstate / ttime 값이 모두 완전히 동일.
- 같은 70MB 원본을 DAT 인덱스 최적화 후 다시 변환: 3.41초. 기존 변환과 6프레임의 72개 결과 배열 및 최종 상태가 동일. 원본의 모든 수치 검증 유지.
- 짧은 2방향 낙하+안정화 전체 완료, 두 번째 낙하로 전달된 native 재료 이력 해시 동일 확인.

이는 짧은 Linux 테스트 측정치입니다. 사용자의 20~40GB 사례나 Windows 전체 실행 시간에 같은 감소율을 보장하는 수치는 아닙니다. 새 라이브러리 설치는 없습니다. 기존 템플릿·runs·솔버·라이브러리를 보존합니다.
